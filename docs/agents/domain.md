# Domain docs

本项目采用 single-context：根目录的 `GLOSSARY.md` 定义领域术语，`docs/adr/` 保存领域决策。

## 阅读入口

探索领域行为、制定方案、编写规格或修改实现前：

1. 阅读 [GLOSSARY.md](../../GLOSSARY.md)，使用已定义术语描述业务概念。
2. 阅读 [docs/adr/](../adr/) 中与任务相关的决策；当前识别与分类任务涉及时间回退、日金额历史匹配和节点优先策略。
3. 实现规格时同时读取对应 issue，理解验收条件和范围。

若术语表或相关决策文件不存在，继续工作；这些文档在术语与决策实际明确时由领域建模流程逐步形成，无需预先补空文件。

## 使用约定

- issue、规格、代码讨论及测试名称沿用术语表定义；区分来源应用、凭证来源和付款账户。
- 新概念先检查是否已有对应术语，确有缺口时在领域建模时记录。
- 方案与现有 ADR 冲突时，明确指出冲突及重开决策的理由；实现不能静默改变已确认行为。
- 保留现有领域文档，按业务决策增量更新。本项目不另建多上下文目录。
