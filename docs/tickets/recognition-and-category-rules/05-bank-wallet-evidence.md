# 05：银行凭证匹配实际账户并守住入账门槛

## Parent

[Issue #5：交易识别与自动分类升级规格](https://github.com/karl1179090/huayoupu-ledger/issues/5)

## What to build

主动识别微信内的单张银行交易凭证时，依据银行与卡尾选择实际银行卡；账户或方向不明确时进入待确认，确认前不扣任何钱包。

本项覆盖父规格验收编号：T10、T11、T12。继续遵守父规格的离线处理、合成测试数据和不追溯旧账单等约定；在本项完成时执行受影响的检查。

## Acceptance criteria

- [ ] 摇一摇、快捷方式和图片导入可处理已适配单张银行凭证；自动监控继续限定既有即时支付结果，不被动扫描银行通知。
- [ ] 在同一交易区块内组合银行、交易类型和尾号；银行＋卡尾唯一匹配时选卡，无卡尾但本地唯一同银行账户时允许匹配并记录依据。
- [ ] 明确卡尾不符时不降级成银行名匹配；多候选、无账户或冲突保留待确认，不回退微信或默认账户。
- [ ] “网上快捷支付”等已适配类型可提供方向证据；泛化“交易成功提醒”不一律作为支出，余额及余额差不能单独推断方向或交易身份。
- [ ] 实际扣款证据优先于付款偏好，人工锁定账户保留优先；普通非银行支付仍遵守其既有适用规则。
- [ ] 正式入账门槛与钱包效果共同落实：账户／方向未定时所有钱包余额不变，确认后仅正确账户产生一次影响。
- [ ] 账户证据、选择依据和确认状态经过重启／备份保持；覆盖成功、不符、多账户、无账户、无尾号唯一及人工锁定，用端到端资金断言验证。
