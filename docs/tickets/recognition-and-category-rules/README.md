# 交易识别与自动分类：开发任务

状态：用户已授权按此拆分实施；15 项已发布为父规格的子 issue #6–#20，均使用 `ready-for-agent` 标签及 GitHub 原生阻塞关系。下列 01–15 为规划编号，实际 issue 编号及依赖映射见 [tracker-map.json](tracker-map.json)。

## 拆分原则

- 每项包含可独立演示或验证的完整结果，以及必要的数据、界面／反馈、兼容和行为测试。基本持久化、备份及测试跟随各项交付，最后另做组合恢复和真机验收。
- 01 是识别链路的前置兼容重构，完成后再扩展这条链路；02 是独立的分类目录工作。优先增加兼容结构再迁移调用，不做一次性替换共享字段的大范围重构。
- 10 将多笔自动入账、日金额业务匹配、候选幂等和中断恢复作为一个完整的资金提交能力验收。
- 只把真实技术前置项标为阻塞：银行凭证和时间可在 03 之后分别推进，分类与节点选路无需等待多笔功能，规则测试不阻塞备份实现。
- 已按依赖顺序在用户 fork 创建子 issue，关联父 issue 并使用 GitHub 原生阻塞边；每项应用 `ready-for-agent`。发布任务时保留父 issue 的正文、状态及标签。
- 发布时可开始的前沿是 01、02；执行中的可开始任务以 GitHub 原生阻塞项状态为准。任务显示 `ready-for-agent` 表示规格完整，有未完成阻塞项时仍需等待。

## 任务清单

1. **[兼容扩展单笔识别提交链路](01-single-recognition-prefactor.md)** — 阻塞项：无。交付：在统一交易候选结构下完成已有单笔识别、入账、补充凭证和恢复，给后续节点与多笔入口提供可复用的提交边界，保持现有用户行为。

2. **[统一分类目录并提供基础管理](02-category-directory-management.md)** — 阻塞项：无。交付：用户在设置中按收入、支出添加分类、改名、排序和选图标，记账、编辑、筛选及统计使用同一目录；升级后原有分类归属保持不变。

3. **[保留并展示单笔凭证的结构化信息](03-structured-single-receipt.md)** — 阻塞项：01。交付：识别单笔支付结果后，账单可保留商家、订单内容、服务商和凭证来源及其依据，缺少的字段保持缺失，为分类与钱包匹配提供可信输入。

4. **[识别交易日期并固定缺时间回退](04-transaction-time-fallback.md)** — 阻塞项：03。交付：凭证有日期时按页面日期记账，没有可用交易时间时直接按本次识别时间入账，历史图片也适用；重试和跨日恢复保持日期稳定。

5. **[银行凭证匹配实际账户并守住入账门槛](05-bank-wallet-evidence.md)** — 阻塞项：03。交付：主动识别微信内的单张银行交易凭证时，依据银行与卡尾选择实际银行卡；账户或方向不明确时进入待确认，确认前不扣任何钱包。

6. **[按商家自动分类并固定任务规则快照](06-merchant-rules-and-snapshots.md)** — 阻塞项：01、02。交付：用户在设置中建立按商家匹配的自定义规则，新识别按规则归类；修改规则不会改变历史账单、人工分类或已排队任务。

7. **[支持订单内容组合条件和内置规则管理](07-compound-order-rules.md)** — 阻塞项：03、06。交付：用户可用订单内容及来源区分同一商家的不同用途，通过包含、等于、不包含与全部／任一条件配置分类，并单独管理内置规则。

8. **[删除分类时迁移账单、规则及排队目标](08-category-delete-replacement.md)** — 阻塞项：06。交付：用户删除被使用的分类时先看到影响，再选择同方向替代分类，一次完成账单和规则迁移；排队任务使用有效替代目标。

9. **[测试规则并从账单预填新规则](09-rule-preview-from-bill.md)** — 阻塞项：07。交付：用户可用测试输入或已有账单查看最终命中及原因，也可从账单编辑页预填规则，经保存后影响未来识别。

10. **[多张银行交易卡按日金额入账并恢复](10-multi-bank-day-amount.md)** — 阻塞项：04、05。交付：主动识别同屏多张银行交易卡，每卡独立解析并按日期与金额查历史，未匹配的合格候选全部入账；结果逐项可见，中断后不会漏记或重复扣款。

11. **[识别混排通知及查看器中的交易凭证](11-mixed-and-nested-receipts.md)** — 阻塞项：04、05。交付：处理服务通知与实际扣款卡混排、查看器内嵌银行摘要等页面，排除外围内容，保留正确商家与账户证据，并按信息是否充分入账或待确认。

12. **[已验证单笔版式直接使用无障碍节点](12-verified-node-fast-path.md)** — 阻塞项：04。交付：现场已验证的单笔支付结果直接用节点识别、保留截图并正常入账；未知或异常版式回退一次 OCR，结果可走同一个分类和提交入口。

13. **[节点识别容忍普通截图失败并复用图标](13-node-screenshot-icons.md)** — 阻塞项：12。交付：可靠节点已取得时，普通截图失败仍可保存账单并标明缺图；商家图标优先复用缓存，无缓存显示默认图标。

14. **[完整恢复与合并新增分类和识别状态](14-backup-merge-roundtrip.md)** — 阻塞项：07、08、10、11、13。交付：用户可把包含自定义分类、规则、银行证据、时间依据及未完成识别任务的完整备份恢复或合并到另一账本，并继续处理而不重分或重扣。

15. **[完成组合流程回归及真机适配验收](15-combined-acceptance-device.md)** — 阻塞项：09、14。交付：把两项升级组合验证为可交付版本，确认节点／OCR、多笔、银行钱包和自定义分类相互协作，并明确实际设备适配与性能范围。
