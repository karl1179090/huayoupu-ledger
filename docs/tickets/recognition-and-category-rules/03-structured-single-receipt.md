# 03：保留并展示单笔凭证的结构化信息

## Parent

[Issue #5：交易识别与自动分类升级规格](https://github.com/karl1179090/huayoupu-ledger/issues/5)

## What to build

识别单笔支付结果后，账单可保留商家、订单内容、服务商和凭证来源及其依据，缺少的字段保持缺失，为分类与钱包匹配提供可信输入。

本项覆盖父规格验收编号：T03、T28。继续遵守父规格的离线处理、合成测试数据和不追溯旧账单等约定；在本项完成时执行受影响的检查。

## Acceptance criteria

- [ ] OCR 单笔结果通过统一候选进入账本；将本交易区块中的商家、商品／交易说明、订单备注、服务商、来源应用及凭证来源分别保存。
- [ ] 账单详情可核对已有业务字段；页面仅有成功状态、简短商家和金额时保留短名称，不补猜门店、商品或订单号，缺商家显示未提供。
- [ ] 金额、状态或方向未通过既有业务校验时不因新增字段而正式入账；本项不扩张自动监控范围。
- [ ] 字段保存必要原始文字、来源和区块关联；来源应用不等同于付款账户，银行作者及服务商不自动成为商家。
- [ ] 订单内容只取本交易区块的业务文字；广告、优惠券、积分、导航及用户手写记账备注不作为订单内容。
- [ ] 新字段经过重启和备份恢复仍可读取；旧记录缺少新字段时可继续查看，不批量回填推测信息或改变原类别。
- [ ] 用合成单笔凭证覆盖详细内容、简短成功页、外围干扰及缺字段，并从识别提交到详情验证结果。
