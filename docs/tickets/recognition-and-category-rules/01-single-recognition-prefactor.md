# 01：兼容扩展单笔识别提交链路

## Parent

[Issue #5：交易识别与自动分类升级规格](https://github.com/karl1179090/huayoupu-ledger/issues/5)

## What to build

在统一交易候选结构下完成已有单笔识别、入账、补充凭证和恢复，给后续节点与多笔入口提供可复用的提交边界，保持现有用户行为。

本项覆盖父规格验收编号：T21、T33。继续遵守父规格的离线处理、合成测试数据和不追溯旧账单等约定；在本项完成时执行受影响的检查。

## Acceptance criteria

- [ ] 先新增兼容的候选容器、候选身份与提交结果表示，让当前单笔入口以一个候选走通；旧调用、旧任务及已有回执仍可读取和恢复。
- [ ] 从现有识别处理入口验证：相同输入产生相同账单字段、状态、分类、钱包影响、截图及用户反馈，不启用多笔日金额规则。
- [ ] 同一单笔任务重试或重启恢复只生成一条账单和一次钱包影响；账本已提交但任务写回失败时复用回执，不重新识别。
- [ ] 保留补充凭证、人工编辑、退款、本人互转和手续费的专门语义，以及授权撤销时的原有行为。
- [ ] 兼容扩展先落地再接入后续功能，避免一次性替换所有共享字段；仅为本次识别契约建立必要兼容层。
- [ ] 沿用识别处理与账本真实测试数据库覆盖成功、取消、提交回滚及恢复；原有相关检查保持通过。
