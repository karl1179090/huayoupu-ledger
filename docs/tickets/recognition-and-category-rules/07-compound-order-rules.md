# 07：支持订单内容组合条件和内置规则管理

## Parent

[Issue #5：交易识别与自动分类升级规格](https://github.com/karl1179090/huayoupu-ledger/issues/5)

## What to build

用户可用订单内容及来源区分同一商家的不同用途，通过包含、等于、不包含与全部／任一条件配置分类，并单独管理内置规则。

本项覆盖父规格验收编号：T26、T27、T28、T34。继续遵守父规格的离线处理、合成测试数据和不追溯旧账单等约定；在本项完成时执行受影响的检查。

## Acceptance criteria

- [ ] 在既有规则编辑流程中支持商家及订单内容条件、可选来源限制、包含／等于／不包含、全部／任一满足；目标与方向校验一致。
- [ ] 来源依据实际包名或明确平台证据，区分图片导入与现场来源，不从任意全文猜测来源。
- [ ] 比较时规范化全半角、大小写及无意义空白并保留原文；缺字段对所有文字运算均不匹配，包括“不包含”。
- [ ] 广告、优惠券、积分、导航、客服和手写记账备注不混入；不支持正则、任意嵌套、模糊商家或 OCR 数字猜测。
- [ ] 自定义规则保持列表首条命中优先；内置规则可分别启停，并能复制成自定义规则后编辑。
- [ ] 扩展后的完整条件及内置启停状态纳入任务快照、命中解释、持久化与备份，旧规则及旧快照继续恢复。
- [ ] 演示同一平台的不同订单用途分别归类，覆盖组合关系、负向缺字段、来源限制、内置复制和排序截获；结果不改变方向或钱包。
