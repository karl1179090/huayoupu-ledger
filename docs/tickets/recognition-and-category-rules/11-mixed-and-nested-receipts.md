# 11：识别混排通知及查看器中的交易凭证

## Parent

[Issue #5：交易识别与自动分类升级规格](https://github.com/karl1179090/huayoupu-ledger/issues/5)

## What to build

处理服务通知与实际扣款卡混排、查看器内嵌银行摘要等页面，排除外围内容，保留正确商家与账户证据，并按信息是否充分入账或待确认。

本项覆盖父规格验收编号：T07、T08。继续遵守父规格的离线处理、合成测试数据和不追溯旧账单等约定；在本项完成时执行受影响的检查。

## Acceptance criteria

- [ ] 主动触发及图片导入可定位嵌套凭证，排除外层账单记录时间、状态栏、查看器控件和推荐内容。
- [ ] 只有银行与金额的摘要保留已知字段，缺时间使用固定识别时间；未知方向或账户仍待确认，未确认前不扣余额。
- [ ] 服务开通或偏好通知不单独生成消费；实际扣款卡可独立识别，并区分实际商家、扣费服务商和消息出具方。
- [ ] 实际“通过零钱扣款”可作为零钱账户证据；“优先从零钱支付”不作为已执行付款证明，保持账户歧义处理。
- [ ] 订单内容和商家只来自本交易区块，广告、积分、余额及非交易文字不污染分类输入；不自动点击其他页面补信息。
- [ ] 账单详情和凭证留档可追溯所用证据，新增区块来源随持久化及备份保留；本项不改既有类别和时间。
- [ ] 用合成的内嵌摘要、服务通知＋扣款卡及只有通知页面验证新增记录数、字段归属和钱包影响；识别后离开页面仍使用已保存证据。

## Blocked by

- 规划 05：银行凭证匹配实际账户并守住入账门槛
