# 识别反馈与分类规则交互设计

## Context

识别批次保存当时的候选及提交结果，用户可在之后确认账单。快捷方式需先核对窗口和采集授权，成功后由识别队列处理凭证。分类规则测试可试跑草稿或已保存的配置。

## Decisions

1. 批次读取时用关联账单的当前状态更新待确认卡和汇总。账单确认沿用原入账事务和防重复提交机制。若仍有缺项，编辑窗保留已填内容，并使用最新的账单版本继续提交。
2. 快捷方式在获取凭证后显示「正在识别」。找不到窗口、授权失效、页面切换或截图超时等中止路径显示相应原因。识别结果以提交回执和当前账单为准，已记过的交易有明确结束提示。
3. 「自动分类规则」默认打开已有规则列表。新增或编辑有独立表单，从表单进入草稿测试后返回时保留输入。保存成功进入使用已保存规则的测试页。
4. 银行名称和尾号共同匹配时采用唯一匹配项。缺少其中一项时，只有另一项唯一定位且没有冲突，才自动绑定可用银行卡。账户未定的账单确认前保持钱包余额原值。
5. 单笔普通收支的成功浮窗读取已保存账单的分类。原地小窗复用账单保存和钱包联动逻辑，初始显示分类、金额、钱包、备注，展开后编辑商家、时间和收支方向。分类、钱包和方向都在同一个小窗内选择，避免旧版 Android 的焦点切换问题。

## Verification

原地编辑通过 Android 11 和 14 模拟器的合成账单测试。测试在来源应用上打开小窗，修改分类和金额，保存后核对原账单及钱包余额。验证汇总见 [实施与验证记录](tasks.md)。
