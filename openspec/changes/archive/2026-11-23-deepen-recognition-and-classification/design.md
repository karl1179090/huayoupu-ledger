# 识别与分类模块设计

## Context

账本、识别任务和截图分别持久化。任务创建时固定整套分类规则，账本在同一事务中提交账单、钱包影响和提交回执。完整备份恢复使用已有的跨库事务，处理结果与截图可能在进程重启后重新读取。四项业务契约见 [变更提案](proposal.md)和各能力规格。

## Goals

- 每个模块集中持有自己的一组业务判定，使正常执行、恢复和测试通过相同入口观察结果。
- 以现有识别入口、账本事务和完整备份流程验证行为。覆盖旧任务、旧回执及历史备份。
- 按 [ADR 0001](../../../../docs/adr/0001-use-recognition-time-for-missing-transaction-time.md)沿用固定识别时间，按 [ADR 0002](../../../../docs/adr/0002-match-multiple-transactions-by-day-and-amount.md)处理历史匹配，按 [ADR 0003](../../../../docs/adr/0003-use-accessibility-for-verified-layouts.md)执行现场选路、采集授权、窗口核对和隐私检查。

## Decisions

### 1. 由任务生命周期共用分类引用判定

统一使用任务状态、已保存批次的未完成项、重试证据和持久授权判断失败或已取消的批次能否继续。实时执行资格额外取决于当前采集权限和队列容量。这些临时条件单独用于运行前检查，防止可以继续的任务因暂时停顿失去原有分类归属。

任务状态变化、持久撤权、进程启动、备份恢复和分类删除复核共用该判定。删除预览和确认在生成影响及指纹前核对相关引用，确认和分类迁移沿用同一账本事务。完整备份导入在其跨库事务中依据还原后的任务、截图和授权重算。历史数据在现有启动及删除复核入口按需校正。

保留引用时，继续按识别时保存的整套规则和替代关系计算目标。缩到剩余候选实际使用的分类会改变完整备份对活动规则快照的目标校验，见 [ADR 0004](../../../../docs/adr/0004-retain-category-references-while-batches-can-retry.md)。

### 2. 由配置模块持有完整配置的读写和校验

把当前自定义分类规则、内置分类规则、最终版本与替代关系作为一个校验对象。配置信息的拼装、序列化、读回约束和容量检查集中在同一模块。各调用路径提供操作意图，模块从当时配置生成并校验完整结果。试跑读取校验结果用于展示，保存使用相同规则重新准备并写入。

分类删除与规则目标迁移一并提交。备份按现有冲突合并规则生成完整结果，验证成功后由已有跨库事务发布。以最终序列化数据的大小校验可以覆盖分类替代占用、多字节文字与最终版本长度同时变化的情况。当前配置与任务冻结快照各自承担规则编辑与历史重试，沿用已有配置及备份格式。

### 3. 共用本次提交事实，按当前账单生成即时提示

账本提交结果记录本次处理的实际效果，供正常完成与中断恢复共用。重复处理、仅补充凭证资料、实际新入账或更新退款具有可区分的结果。由钱包和退款实际产生的变动判定效果，当前账单的退款历史可供展示账单详情。来自另一任务的支付事件回执用于判定已处理。

为新回执保存恢复所需的最小结果信息，与账单及钱包影响原子提交，并在完整备份中往返。旧回执读取时允许结果信息缺省。人工确认退款后保留真实退款效果与回执关联，重启恢复可回到最终账单。任务列表据回执恢复处理事实，符合提示条件时再依据账单是否仍可查看及是否待核对生成提示和链接。见 [ADR 0005](../../../../docs/adr/0005-base-recognition-feedback-on-committed-effects.md)。

### 4. 由 OCR 解析模块判断凭证范围和拒绝原因

OCR 解析结果明确携带凭证范围、对应原文和处理结论，供识别编排选择单笔或批次的提交路径。解析模块先使用已有版式与几何信息分块，在各自凭证内应用状态词及字段校验。可保存完整截图用于查阅，每个候选的入账证据使用自己的凭证原文。

已分块的单个候选仍携带块身份通过现有批次链路。下游继续按解析后进入批次的候选数和交易类型选用历史匹配。缺交易时间使用已固定的识别时间，付款账户证据不足时走已有待核对处理。按凭证范围报告结论可减少调用者对特殊候选 ID 和整页文字适用范围的推断。

## Risks / Trade-offs

- **撤权、清理或重试与删除并发** → 使用持久授权快照和当前批次证据核对引用，保持账本锁与授权锁的获取顺序。分类确认以本次核对结果为准，过期预览要求重新确认。
- **单独可读的配置合并后无法读回** → 以完整序列化数据校验最终配置，并复用分类删除和完整恢复的事务边界。
- **旧回执信息不足，或来自其他任务的事件回执** → 仅依据可确认的处理事实恢复状态。新结果随同原提交持久化，验证旧库升级、旧备份恢复及退款重定向。
- **解析重构误改变查重或付款账户判断** → 保留单项批次的区块证据，按入账前候选数执行既有日金额规则。以真实入口测试失败卡隔离、付款账户待核对和资金效果。

## Migration Plan

按 [任务清单](tasks.md) 的四组顺序实施。启动和显式删除复核校正已有任务的分类引用。回执结果字段需要变更时使用仓库既有数据库升级流程，完整备份可继续读取历史格式，缺少详细结果的旧回执保留可确认的处理事实。以旧备份导入、部分成功批次恢复和重复恢复验证兼容。
